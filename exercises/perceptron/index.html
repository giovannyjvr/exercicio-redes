    Como reproduzir

    Todos os números deste relatório saem de uma única execução. A partir da raiz do repositório:

    python -m pip install -r requirements.txt
python docs/exercises/perceptron/code/run_all.py
mkdocs build --strict

    run_all.py regenera as seis figuras em figures/, imprime todos os números no terminal e os grava em results/metrics.json.

    Estrutura do código. O perceptron vive em code/perceptron.py e é incluído neste relatório pelo próprio arquivo, via --8<--.

    Arquivo Papel
    perceptron.py A implementação do zero: step, predict, regra de atualização e laço de treino.
    run_all.py Ponto de entrada único: gera os dados, treina, produz as seis figuras e salva as métricas.

    Nenhuma biblioteca fornece o modelo

    A ativação, a predição, a regra de atualização e o laço de treino são escritos à mão. O NumPy entra apenas como álgebra linear (produto escalar, permutação, amostragem das gaussianas). Não há sklearn neste exercício — nem Perceptron, nem SGDClassifier, nem qualquer fit.

    A semente é criada uma única vez, em run_all.py, como rng = np.random.default_rng(42), e o mesmo objeto é passado à geração dos dados e a cada treino, sempre na mesma ordem.

    """Perceptron de camada única, escrito do zero.

Nada aqui vem de biblioteca de modelo: a ativação (`step`), a predição, a regra
de atualização e o laço de treino são implementados à mão, com NumPy usado
apenas como álgebra linear. É a mesma implementação usada nos dois exercícios —
o Exercise 2 a reaproveita **sem alterar uma linha**.

Convenção de rótulos: :math:`y \\in \\{0, 1\\}`. A regra de atualização é

.. math:: \\mathbf{w} \\leftarrow \\mathbf{w} + \\eta (y - \\hat{y}) \\mathbf{x},
          \\qquad b \\leftarrow b + \\eta (y - \\hat{y})

O erro :math:`(y - \\hat{y})` vale 0 quando a predição está certa — amostras
corretas não geram atualização — e :math:`\\pm 1` nos dois tipos de engano.
A forma ``w += eta * y * x``, comum em livros, pertence à convenção
:math:`y \\in \\{-1, +1\\}`: com rótulos 0/1 ela nunca atualizaria na classe 0 e
o perceptron jamais corrigiria um falso positivo.
"""

from __future__ import annotations

from typing import Any

import numpy as np


def step(z: np.ndarray | float) -> np.ndarray | float:
    """Degrau de Heaviside: 1 se ``z >= 0``, 0 caso contrário."""
    return np.where(np.asarray(z) >= 0.0, 1, 0)


def predict(X: np.ndarray, w: np.ndarray, b: float) -> np.ndarray:
    """Predição do perceptron: ``step(X @ w + b)``."""
    return step(X @ w + b)


def accuracy(X: np.ndarray, y: np.ndarray, w: np.ndarray, b: float) -> float:
    """Fração de acertos de ``(w, b)`` sobre o conjunto inteiro."""
    return float(np.mean(predict(X, w, b) == y))


def train(
    X: np.ndarray,
    y: np.ndarray,
    rng: np.random.Generator,
    *,
    eta: float = 0.01,
    max_epochs: int = 100,
) -> dict[str, Any]:
    """Treina o perceptron e devolve pesos finais, pesos *pocket* e histórico.

    Parâmetros seguem o enunciado: inicialização ``rng.normal(0, 0.01, size=2)``
    com ``b = 0`` (nunca do zero — o item D do Exercise 1 depende disso), taxa de
    aprendizado ``eta`` e parada quando uma época inteira não produz nenhuma
    atualização, ou ao atingir ``max_epochs``.

    O **pocket** é a única coisa acrescentada ao laço: sempre que uma atualização
    deixa a acurácia sobre o conjunto completo acima da melhor já vista, copia-se
    ``(w, b)``. Em dados separáveis ele converge para os pesos finais e não muda
    nada; em dados sobrepostos ele é o que salva o melhor hiperplano encontrado.
    Mantê-lo sempre ligado é o que permite usar esta função, sem modificação, nos
    dois exercícios.
    """
    n_features = X.shape[1]
    w = rng.normal(0.0, 0.01, size=n_features)
    b = 0.0

    pocket_w, pocket_b = w.copy(), b
    pocket_accuracy = accuracy(X, y, w, b)
    pocket_epoch = 0

    history: list[dict[str, float]] = []
    epochs_run = 0
    converged = False

    for epoch in range(1, max_epochs + 1):
        epochs_run = epoch
        # Embaralha a cada época: os dados chegam agrupados por classe (1000 da
        # classe 0, depois 1000 da classe 1) e percorrê-los nessa ordem faria o
        # perceptron ver uma classe inteira antes da outra. A permutação sai do
        # mesmo rng, então continua reprodutível.
        order = rng.permutation(len(X))
        updates = 0

        for index in order:
            x_i, y_i = X[index], y[index]
            y_hat = step(np.dot(w, x_i) + b)
            error = y_i - y_hat
            if error != 0:
                w = w + eta * error * x_i
                b = b + eta * error
                updates += 1
                # Pocket: só faz sentido medir depois de uma atualização, porque
                # sem atualização os pesos não mudaram.
                current = accuracy(X, y, w, b)
                if current > pocket_accuracy:
                    pocket_accuracy = current
                    pocket_w, pocket_b = w.copy(), b
                    pocket_epoch = epoch

        history.append(
            {
                "epoch": epoch,
                "updates": updates,
                "accuracy": accuracy(X, y, w, b),
                "pocket_accuracy": pocket_accuracy,
            }
        )

        if updates == 0:
            # Uma passagem completa sem nenhuma atualização: todo ponto está do
            # lado certo da fronteira e nada mais mudaria.
            converged = True
            break

    return {
        "w": w,
        "b": float(b),
        "accuracy": accuracy(X, y, w, b),
        "epochs": epochs_run,
        "converged": converged,
        "pocket_w": pocket_w,
        "pocket_b": float(pocket_b),
        "pocket_accuracy": pocket_accuracy,
        "pocket_epoch": pocket_epoch,
        "history": history,
        "eta": eta,
        "max_epochs": max_epochs,
    }

    """Ponto de entrada único da entrega *Perceptron*.

Gera os dois datasets, treina o perceptron escrito do zero em
:mod:`perceptron`, produz as seis figuras e imprime — além de salvar em
``results/metrics.json`` — todos os números citados no relatório.

Uso, a partir da raiz do repositório::

    python docs/exercises/perceptron/code/run_all.py

**A semente é criada aqui, uma única vez**, como ``rng =
np.random.default_rng(42)``, e o mesmo objeto é passado a cada geração de dados
e a cada treino, sempre na mesma ordem. Nada é reinicializado no meio.
"""

from __future__ import annotations

import json
import sys
from pathlib import Path
from typing import Any

import matplotlib

# Backend sem interface gráfica: o script roda no GitHub Actions, que não tem display.
matplotlib.use("Agg")

import matplotlib.pyplot as plt  # noqa: E402
import numpy as np  # noqa: E402

sys.path.insert(0, str(Path(__file__).resolve().parent))

from perceptron import accuracy, predict, train  # noqa: E402

BASE = Path(__file__).resolve().parents[1]
FIGURES = BASE / "figures"
RESULTS = BASE / "results"
DPI = 150

SEED = 42
N_PER_CLASS = 1000
CLASS_COLORS = ("#1f77b4", "#d62728")

# Exercise 1 — nuvens bem separadas.
SEPARABLE = {
    0: {"mean": [1.5, 1.5], "cov": [[0.5, 0.0], [0.0, 0.5]]},
    1: {"mean": [5.0, 5.0], "cov": [[0.5, 0.0], [0.0, 0.5]]},
}
# Exercise 2 — médias próximas e dispersão três vezes maior.
OVERLAPPING = {
    0: {"mean": [3.0, 3.0], "cov": [[1.5, 0.0], [0.0, 1.5]]},
    1: {"mean": [4.0, 4.0], "cov": [[1.5, 0.0], [0.0, 1.5]]},
}

EXPECTED_FIGURES = [
    "figure_01_separable_scatter.png",
    "figure_02_separable_boundary.png",
    "figure_03_separable_accuracy.png",
    "figure_04_overlapping_scatter.png",
    "figure_05_overlapping_boundaries.png",
    "figure_06_overlapping_accuracy.png",
]


def save_figure(fig: plt.Figure, filename: str) -> str:
    """Salva em ``figures/`` com nome determinístico e fecha a figura."""
    FIGURES.mkdir(parents=True, exist_ok=True)
    fig.tight_layout()
    fig.savefig(FIGURES / filename, dpi=DPI)
    plt.close(fig)
    return filename


def generate(rng: np.random.Generator, spec: dict[int, dict[str, Any]]) -> tuple[np.ndarray, np.ndarray]:
    """Amostra ``N_PER_CLASS`` pontos 2D por classe a partir de normais multivariadas."""
    parts_x, parts_y = [], []
    for label, params in spec.items():
        parts_x.append(
            rng.multivariate_normal(np.asarray(params["mean"]), np.asarray(params["cov"]), size=N_PER_CLASS)
        )
        parts_y.append(np.full(N_PER_CLASS, label))
    return np.vstack(parts_x), np.concatenate(parts_y)


def _scatter(ax: plt.Axes, X: np.ndarray, y: np.ndarray) -> None:
    """Dispersão com uma cor por classe."""
    for label, color in zip((0, 1), CLASS_COLORS):
        points = X[y == label]
        ax.scatter(
            points[:, 0], points[:, 1], s=9, alpha=0.5, color=color,
            edgecolors="none", label=f"Classe {label}",
        )


def _boundary_line(w: np.ndarray, b: float, xlim: tuple[float, float]) -> tuple[np.ndarray, np.ndarray]:
    """Pontos da reta ``w · x + b = 0`` dentro de ``xlim``.

    Isolando :math:`x_2`: :math:`x_2 = -(w_1 x_1 + b) / w_2`.
    """
    xs = np.linspace(*xlim, 200)
    return xs, -(w[0] * xs + b) / w[1]


def figure_scatter(X: np.ndarray, y: np.ndarray, title: str, filename: str) -> str:
    """Figuras 1 e 4 — dispersão dos 2000 pontos, uma cor por classe."""
    fig, ax = plt.subplots(figsize=(7.5, 6.0))
    _scatter(ax, X, y)
    ax.set_xlabel("$x_1$")
    ax.set_ylabel("$x_2$")
    ax.set_title(title)
    ax.legend(loc="upper left")
    ax.grid(alpha=0.2, linestyle=":")
    return save_figure(fig, filename)


def figure_boundary(
    X: np.ndarray,
    y: np.ndarray,
    models: list[dict[str, Any]],
    title: str,
    filename: str,
) -> str:
    """Figuras 2 e 5 — fronteira(s) sobre os dados, com os erros destacados.

    ``models`` traz um ou dois conjuntos de pesos; os pontos mal classificados
    marcados são os do **primeiro** modelo da lista.
    """
    fig, ax = plt.subplots(figsize=(8.5, 6.5))
    _scatter(ax, X, y)

    xlim = (float(X[:, 0].min() - 0.5), float(X[:, 0].max() + 0.5))
    ylim = (float(X[:, 1].min() - 0.5), float(X[:, 1].max() + 0.5))

    wrong = predict(X, models[0]["w"], models[0]["b"]) != y
    ax.scatter(
        X[wrong][:, 0], X[wrong][:, 1], s=46, facecolors="none",
        edgecolors="black", linewidths=0.8,
        label=f"Mal classificados por «{models[0]['label']}» ({int(wrong.sum())})",
    )

    for model, style in zip(models, ("-", "--")):
        xs, ys = _boundary_line(model["w"], model["b"], xlim)
        ax.plot(
            xs, ys, style, color=model.get("color", "black"), linewidth=2.2,
            label=f"Fronteira — {model['label']} (acurácia {model['accuracy'] * 100:.2f}%)",
        )

    ax.set_xlim(*xlim)
    ax.set_ylim(*ylim)
    ax.set_xlabel("$x_1$")
    ax.set_ylabel("$x_2$")
    ax.set_title(title)
    ax.legend(loc="upper left", fontsize=8.5)
    ax.grid(alpha=0.2, linestyle=":")
    return save_figure(fig, filename)


def figure_accuracy(
    curves: list[dict[str, Any]], title: str, filename: str, *, ylim: tuple[float, float] | None = None
) -> str:
    """Figuras 3 e 6 — acurácia (em %) por época."""
    fig, ax = plt.subplots(figsize=(8.5, 5.2))
    for curve in curves:
        ax.plot(
            curve["epochs"], [v * 100 for v in curve["values"]],
            marker=curve.get("marker", "o"), markersize=4, linewidth=1.9,
            color=curve["color"], label=curve["label"],
        )
    ax.set_xlabel("Época")
    ax.set_ylabel("Acurácia no conjunto completo (%)")
    ax.set_title(title)
    if ylim:
        ax.set_ylim(*ylim)
    ax.grid(alpha=0.25, linestyle=":")
    ax.legend(loc="lower right")
    return save_figure(fig, filename)


def exercise_1(rng: np.random.Generator) -> dict[str, Any]:
    """Exercise 1 — dados separáveis."""
    X, y = generate(rng, SEPARABLE)
    assert X.shape == (2 * N_PER_CLASS, 2) and np.bincount(y).tolist() == [N_PER_CLASS] * 2

    fig1 = figure_scatter(
        X, y,
        "Figura 1 — Dados separáveis: 1000 pontos por classe\n"
        r"($\mu_0 = [1.5, 1.5]$, $\mu_1 = [5, 5]$, $\Sigma = 0.5\,I$)",
        EXPECTED_FIGURES[0],
    )

    # A magnitude da inicialização e o ||x|| médio sustentam, no item D, o
    # argumento sobre o peso relativo entre o vetor inicial e as correções.
    # Reproduz o sorteio de train() sem consumir o rng principal.
    init_norm = float(np.linalg.norm(np.random.default_rng(SEED).normal(0.0, 0.01, size=2)))
    mean_norm = float(np.mean(np.linalg.norm(X, axis=1)))

    run = train(X, y, rng, eta=0.01, max_epochs=100)
    fig2 = figure_boundary(
        X, y,
        [{"w": run["w"], "b": run["b"], "accuracy": run["accuracy"], "label": "pesos finais", "color": "black"}],
        f"Figura 2 — Fronteira aprendida ($\\eta = 0.01$, {run['epochs']} épocas)\n"
        "com os pontos mal classificados destacados",
        EXPECTED_FIGURES[1],
    )
    fig3 = figure_accuracy(
        [{
            "epochs": [h["epoch"] for h in run["history"]],
            "values": [h["accuracy"] for h in run["history"]],
            "color": "#1f77b4", "label": r"Acurácia por época ($\eta = 0.01$)",
        }],
        "Figura 3 — Acurácia por época, dados separáveis\n"
        "(o treino para quando uma época inteira não produz nenhuma atualização)",
        EXPECTED_FIGURES[2],
    )

    # Mesmo treino, mudando só a taxa de aprendizado.
    run_fast = train(X, y, rng, eta=1.0, max_epochs=100)

    def direction(w: np.ndarray) -> np.ndarray:
        return w / np.linalg.norm(w)

    dir_slow, dir_fast = direction(run["w"]), direction(run_fast["w"])
    angle = float(np.degrees(np.arccos(np.clip(float(dir_slow @ dir_fast), -1.0, 1.0))))

    print("Exercise 1 — dados separáveis")
    print(f"  eta = 0.01 -> w = [{run['w'][0]:.6f}, {run['w'][1]:.6f}], b = {run['b']:.6f}")
    print(f"               épocas = {run['epochs']} (convergiu: {run['converged']}),"
          f" acurácia = {run['accuracy'] * 100:.2f}%")
    print(f"               direção w/||w|| = [{dir_slow[0]:.6f}, {dir_slow[1]:.6f}], ||w|| = {np.linalg.norm(run['w']):.6f}")
    print(f"  eta = 1.00 -> w = [{run_fast['w'][0]:.6f}, {run_fast['w'][1]:.6f}], b = {run_fast['b']:.6f}")
    print(f"               épocas = {run_fast['epochs']} (convergiu: {run_fast['converged']}),"
          f" acurácia = {run_fast['accuracy'] * 100:.2f}%")
    print(f"               direção w/||w|| = [{dir_fast[0]:.6f}, {dir_fast[1]:.6f}], ||w|| = {np.linalg.norm(run_fast['w']):.6f}")
    print(f"  ângulo entre as duas direções = {angle:.4f}°")
    print(f"  ||x|| médio = {mean_norm:.4f} -> passo em w por erro:"
          f" eta=0.01 soma ~{0.01 * mean_norm:.4f}, eta=1.0 soma ~{1.0 * mean_norm:.4f}")
    print(f"  magnitude típica da inicialização ||w_0|| ~ {init_norm:.6f};"
          f" razão ||w||/||w_0||: eta=0.01 -> {np.linalg.norm(run['w']) / init_norm:.1f}x,"

    Código: run_all.py → generate() e figure_scatter().

    B — Implement the perceptron

    Abordagem. Implementação do zero, em perceptron.py, reutilizada sem alteração no Exercise 2.

    • Predição. \(\hat{y} = \text{step}(\mathbf{w}\cdot\mathbf{x} + b)\), com \(\text{step}(z) = 1\) se \(z \geq 0\) e \(0\) caso contrário.
    • Atualização. Para cada amostra \((\mathbf{x}, y)\):
    \[ \mathbf{w} \leftarrow \mathbf{w} + \eta\,(y - \hat{y})\,\mathbf{x}, \qquad b \leftarrow b + \eta\,(y - \hat{y}) \]
    • Inicialização. \(\mathbf{w} \sim\) rng.normal(0, 0.01, size=2) e \(b = 0\).
    • Taxa de aprendizado. \(\eta = 0.01\).
    • Parada. Quando uma passagem completa não produz nenhuma atualização, ou ao atingir 100 épocas. A acurácia sobre o conjunto completo é registrada ao fim de cada época.

    Por que não \(\mathbf{w} \leftarrow \mathbf{w} + \eta\,y\,\mathbf{x}\)

    Essa forma pertence à convenção \(y \in \{-1, +1\}\). Com rótulos \(0/1\) ela nunca atualizaria na classe 0 — o termo \(y\mathbf{x}\) seria sempre nulo — e o perceptron jamais corrigiria um falso positivo. O fator \((y - \hat{y})\) vale \(0\) quando a predição está certa (amostras corretas não geram atualização) e \(\pm 1\) nos dois tipos de engano, que é exatamente o comportamento desejado.

    Uma escolha de implementação a declarar: os dados são gerados agrupados por classe (1000 da classe 0, depois 1000 da classe 1). Percorrê-los nessa ordem faria o perceptron ver uma classe inteira antes da outra, o que distorce o treino. O laço embaralha a cada época com rng.permutation, usando o mesmo gerador — continua inteiramente reprodutível.

    D — Analysis

    Por que dados separáveis convergem rápido

    A resposta está na própria regra de atualização: o fator \((y - \hat{y})\) é zero para toda amostra classificada corretamente. Uma amostra certa não move \(\mathbf{w}\) nem \(b\) — ela é efetivamente ignorada. Só os erros empurram a fronteira, e cada empurrão a move na direção que corrige aquele erro específico.

    A consequência é que o número de atualizações por época mede quanto trabalho resta, e em dados separáveis ele desce a zero rapidamente. Foi o que aconteceu:

    Época Atualizações Acurácia ao fim da época
    1 20 100.00 %
    2 0 100.00 %

    Como existe um hiperplano que acerta todos os pontos, há um conjunto de pesos em que nenhuma amostra gera erro — e, atingido esse conjunto, o laço vira um ponto fixo: zero atualizações, zero movimento, parada. É isso que o teorema de convergência do perceptron garante para dados linearmente separáveis.

    O que \(\eta\) controla — a comparação \(\eta = 0.01\) contra \(\eta = 1.0\)

    Mesmo treino, mesma inicialização, mesma ordem de embaralhamento; só \(\eta\) muda.

    \(\eta = 0.01\) \(\eta = 1.0\)
    \(\mathbf{w}\) final \([0.007782,\ 0.015401]\) \([5.357647,\ 5.551333]\)
    \(b\) final \(-0.080000\) \(-36.000000\)
    Épocas 2 5
    Acurácia final 100.00 % 100.00 %
    \(\lVert\mathbf{w}\rVert\) 0.017255 7.715029
    Direção \(\mathbf{w}/\lVert\mathbf{w}\rVert\) \([0.450973,\ 0.892538]\) \([0.694443,\ 0.719548]\)
    Atualizações por época \([20,\ 0]\) \([71,\ 3,\ 21,\ 11,\ 0]\)

    As duas corridas chegam a 100 %, mas por fronteiras diferentes: o ângulo entre as duas direções é de 17.1767°.

    O enunciado dá a chave: cada atualização soma \(\eta\mathbf{x}\) a pesos que começaram com magnitude \(\approx 0.01\). Portanto \(\eta\) controla o peso relativo entre a inicialização aleatória e as correções acumuladas:

    Nestes dados \(\lVert\mathbf{x}\rVert\) vale 4.6543 em média, e a inicialização sorteada tem magnitude \(\lVert\mathbf{w}_0\rVert =\) 0.010837. Então:

    • Com \(\eta = 0.01\), cada correção soma magnitude \(\eta\lVert\mathbf{x}\rVert \approx 0.0465\), e o \(\lVert\mathbf{w}\rVert\) final é 0.017255 — apenas 1.6 vez a magnitude inicial. O vetor inicial aleatório ainda está lá, e a direção final é um compromisso entre ele e as 20 correções.
    • Com \(\eta = 1.0\), cada correção soma magnitude \(\approx 4.6543\), e o \(\lVert\mathbf{w}\rVert\) final é 7.715029 — 711.9 vezes a inicialização. O vetor inicial foi completamente apagado; a direção final é essencialmente a soma dos \(\mathbf{x}\) que geraram erro.

    Logo \(\eta\) não controla "se" o perceptron converge em dados separáveis — ambos convergem — mas para qual dos infinitos hiperplanos separadores ele converge.

    Um resultado que vale reportar com honestidade porque contraria a intuição comum: \(\eta = 1.0\) levou mais épocas (5) do que \(\eta = 0.01\) (2), não menos. O histórico de atualizações explica: com passo grande, cada correção joga a fronteira longe e cria novos erros do outro lado — 71 atualizações na primeira época, depois 3, depois 21 de novo, num vai-e-vem até assentar. Com passo pequeno, as 20 correções sutis sobre um vetor inicial que já apontava para um lado razoável bastaram. Taxa maior não significa convergência mais rápida.

    Por que partir de \(\mathbf{w} = \mathbf{0}\), \(b = 0\) tornaria \(\eta\) irrelevante

    Afirmação: se o treino inteiro for executado duas vezes a partir de \(\mathbf{w} = \mathbf{0}\), \(b = 0\) — uma com \(\eta_1\) e outra com \(\eta_2\) — os pesos resultantes diferem apenas pelo fator constante \(c = \eta_2/\eta_1\), de modo que a fronteira de decisão e a contagem de épocas são idênticas.

    Demonstração por indução sobre o número de atualizações. Seja \((\mathbf{w}^{(t)}_1, b^{(t)}_1)\) o estado da corrida com \(\eta_1\) após \(t\) passos, e \((\mathbf{w}^{(t)}_2, b^{(t)}_2)\) o da corrida com \(\eta_2\). A hipótese de indução é

    \[ \mathbf{w}^{(t)}_2 = c\,\mathbf{w}^{(t)}_1, \qquad b^{(t)}_2 = c\,b^{(t)}_1, \qquad c = \eta_2/\eta_1 > 0 . \]

    Base (\(t = 0\)). Ambas começam em \(\mathbf{0}\) e \(0\), e \(c \cdot \mathbf{0} = \mathbf{0}\). Vale.

    Passo. Suponha a hipótese válida em \(t\) e considere a próxima amostra \(\mathbf{x}\) (a ordem é a mesma nas duas corridas, pois depende só do rng). A pré-ativação da segunda corrida é

    \[ \mathbf{w}^{(t)}_2 \cdot \mathbf{x} + b^{(t)}_2 = c\left(\mathbf{w}^{(t)}_1 \cdot \mathbf{x} + b^{(t)}_1\right). \]

    Como \(c > 0\), a multiplicação por \(c\) não muda o sinal. Logo \(\text{step}\) devolve o mesmo \(\hat{y}\) nas duas corridas, e o erro \((y - \hat{y})\) é o mesmo — chame-o de \(e\). As atualizações ficam

    \[ \mathbf{w}^{(t+1)}_2 = c\,\mathbf{w}^{(t)}_1 + \eta_2\,e\,\mathbf{x} = c\left(\mathbf{w}^{(t)}_1 + \tfrac{\eta_2}{c}\,e\,\mathbf{x}\right) = c\left(\mathbf{w}^{(t)}_1 + \eta_1\,e\,\mathbf{x}\right) = c\,\mathbf{w}^{(t+1)}_1, \]

    usando \(\eta_2/c = \eta_1\). O mesmo cálculo vale para \(b\). A hipótese se propaga. \(\blacksquare\)

    Três consequências. (i) As duas corridas cometem exatamente os mesmos erros, na mesma ordem, logo fazem o mesmo número de atualizações e param na mesma época. (ii) A fronteira é o conjunto \(\{\mathbf{x} : \mathbf{w}\cdot\mathbf{x} + b = 0\}\), e multiplicar \((\mathbf{w}, b)\) por \(c > 0\) não altera esse conjunto — é a mesma reta. (iii) Portanto \(\eta\) não tem efeito algum: é puro fator de escala.

    É exatamente por isso que o item B proíbe o início em zero. Com \(\mathbf{w} \sim \mathcal{N}(0, 0.01^2)\) existe uma escala de referência fixa e não nula, que não é reescalada junto com \(\eta\) — e aí \(\eta\) passa a importar, como as duas direções separadas por 17.1767° mostram.

    D — Analysis

    A distância entre a acurácia final e a do pocket

    A melhor reta possível para estes dados acerta cerca de 73 %, e o pocket chegou a 72.30 % — praticamente lá. Os pesos finais ficaram em 58.30 %. A diferença de quase 14 pontos não vem de o perceptron "não ter aprendido": vem de onde a regra de atualização deixa a fronteira.

    Onde a fronteira final está. O centróide dos dados é \([3.5206,\ 3.5521]\). A distância com sinal do centróide até cada fronteira, medida em unidades de \(\lVert\mathbf{w}\rVert\), é:

    Distância com sinal do centróide Pontos classificados como classe 1
    Fronteira final \(+1.8314\) 90.00 %
    Fronteira pocket \(+0.2396\) 57.20 %

    A fronteira final está 1.83 unidades abaixo do centro da nuvem — ela passa pela borda inferior esquerda, não pelo meio. O resultado é que ela rotula 90 % de todos os pontos como classe 1, embora apenas 50 % o sejam. Acerta quase toda a classe 1 e erra quase toda a classe 0: daí os 58.30 %. A fronteira pocket, em contraste, passa a \(0.24\) do centróide — praticamente pelo meio — e divide os rótulos de forma equilibrada (57.20 % positivos).

    Por que o laço a deixa ali. A dica do enunciado é comparar quanto \(b\) se move por erro contra quanto \(\mathbf{w}\) se move. Por atualização:

    \[ \Delta\lVert\mathbf{w}\rVert \le \eta\lVert\mathbf{x}\rVert = 0.01 \times 5.1601 = 0.0516, \qquad |\Delta b| = \eta = 0.0100 . \]

    Com \(\lVert\mathbf{x}\rVert \approx 5.16\) para estes dados, \(\mathbf{w}\) se move 5.16 vezes mais depressa que \(b\) a cada erro. Mas quem posiciona a fronteira ao longo da direção \(\mathbf{w}\) é justamente a razão \(-b/\lVert\mathbf{w}\rVert\). Como \(\mathbf{w}\) cresce rápido e \(b\) se arrasta, o deslocamento não consegue acompanhar a rotação: a reta gira com agilidade mas não desliza até o centro da nuvem. Ela termina onde o último punhado de erros a jogou — e, como em dados sobrepostos há 700+ erros por época, "o último punhado" é essencialmente aleatório. A acurácia final é um sorteio entre os valores que a curva vermelha da Figura 6 visita; nesta execução o sorteio caiu em 58.30 %.

    Figura 3 contra Figura 6, e a hipótese que o teorema exige

    Na Figura 3 a acurácia sobe a 100 % e fica: zero atualização, zero movimento, ponto fixo. Na Figura 6 ela oscila entre 50.00 % e 71.75 % por 100 épocas, com média de 62.83 %, e termina em 58.30 % — mais baixa que a média, sem nenhuma tendência de assentar.

    O teorema de convergência do perceptron garante que, se os dados forem linearmente separáveis, o algoritmo encontra um hiperplano separador em um número finito de atualizações, limitado por \((R/\gamma)^2\), onde \(R\) é o raio dos dados e \(\gamma\) a margem do melhor separador. A hipótese violada aqui é exatamente essa: a separabilidade linear. Com as médias a 1.41 de distância e desvio 1.22, as nuvens se sobrepõem e não existe \((\mathbf{w}^\*, b^\*)\) com erro zero — a margem \(\gamma\) não existe, o limite \((R/\gamma)^2\) é infinito, e o teorema simplesmente não diz nada. Sem um ponto fixo onde pousar, o laço nunca para de corrigir.

    Vale sublinhar o que o teorema nunca prometeu: ele não garante a melhor reta, nem que a acurácia cresça monotonicamente. Mesmo no caso separável ele só promete alguma reta separadora em tempo finito.

    Mais épocas resolvem? E um \(\eta\) menor?

    Nenhum dos dois, e o argumento vem da regra de atualização, não de tentativa e erro.

    Mais épocas, não. A condição de parada é "uma passagem sem nenhuma atualização". Ela exige que todos os 2000 pontos estejam do lado certo — impossível aqui. Então, para qualquer número de épocas, a última época ainda conterá centenas de erros (foram entre 683 e 793 por época nas 100 que rodamos), e cada um deles continuará movendo a fronteira. Rodar 10 000 épocas apenas gera mais amostras da mesma oscilação: o estado final continua sendo o resíduo arbitrário das últimas correções. É por isso que o pocket é necessário — ele é a única coisa que transforma uma trajetória que não converge em uma resposta utilizável, e ele já havia encontrado 71.90 % na primeira época, subindo só até 72.30 % na época 61.

    Um \(\eta\) menor, também não. \(\eta\) multiplica igualmente os dois termos da atualização, \(\eta(y-\hat{y})\mathbf{x}\) e \(\eta(y-\hat{y})\). Diminuí-lo encolhe cada passo, mas não muda quais amostras erram numa dada configuração, nem muda a direção de nenhum passo. A trajetória fica com passos menores e amplitude de oscilação menor — e não é isso que está em jogo. O problema não é o tamanho do passo; é que não existe um ponto de parada. Nenhum valor positivo de \(\eta\) cria uma reta separadora que a geometria dos dados não oferece. No limite \(\eta \to 0\) os pesos praticamente não saem da inicialização aleatória, o que piora a situação em vez de melhorá-la.

    A saída real é mudar o critério, não o passo: guardar o melhor (pocket), trocar a função de perda por uma que penalize a margem em vez de apenas contar erros, ou dar ao modelo uma fronteira não linear.
