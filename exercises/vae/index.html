    Como reproduzir

    O VAE precisa do PyTorch, que fica num requirements separado porque o GitHub Actions apenas constrói o site e não precisa baixá-lo:

    python -m pip install -r requirements.txt
python -m pip install -r requirements-vae.txt
python docs/exercises/vae/code/run_all.py

    O MNIST é baixado automaticamente pelo torchvision em data/ (ignorado pelo Git). Ambiente desta execução: CPU, PyTorch 2.15.0+cpu — 204 s para treinar o modelo \(d = 16\) e 217 s para o \(d = 2\), 20 épocas cada.

    Estrutura do código.

    Arquivo Papel
    vae.py Modelo, reparametrização, os dois termos da perda e o laço de treino.
    run_all.py Ponto de entrada único: dados, os dois treinos, as seis figuras e as métricas.

    O que é escrito à mão

    O autograd é permitido neste exercício, mas as partes específicas do VAE não vêm de biblioteca:

    • a reparametrização \(z = \mu + \sigma \odot \varepsilon\), em VAE.reparameterize;
    • a BCE somada sobre os 784 pixels, em reconstruction_bce;
    • a KL em forma fechada, escrita termo a termo em kl_divergence — nada de torch.distributions.kl_divergence;
    • a amostragem do prior, em VAE.sample.

    Não há classe VAE de biblioteca: encoder e decoder são nn.Sequential montados no próprio arquivo.

    Sementes: torch.manual_seed(42) imediatamente antes de construir cada modelo, e o split com torch.Generator().manual_seed(42). A grade de amostras do prior da Figura 3 usa torch.manual_seed(0), como pedido.

    O conjunto de teste é tocado uma única vez por modelo, para os números finais. Todo o acompanhamento durante o treino é feito na validação.

    """VAE em PyTorch — modelo, perda e laço de treino.

O autograd é permitido neste exercício, mas **as partes específicas do VAE são
escritas à mão**:

* a reparametrização :math:`z = \\mu + \\sigma \\odot \\varepsilon`, em
  :meth:`VAE.reparameterize`;
* a entropia cruzada binária **somada sobre os 784 pixels** e dividida pelo
  tamanho do lote, em :func:`vae_loss`;
* a KL em **forma fechada**, escrita termo a termo em :func:`kl_divergence` —
  não se usa ``torch.distributions.kl_divergence``;
* a amostragem do prior, em :meth:`VAE.sample`.

Nenhuma classe VAE de biblioteca é utilizada: o encoder e o decoder são
``nn.Sequential`` montados aqui.
"""

from __future__ import annotations

from typing import Any

import torch
import torch.nn.functional as F
from torch import nn

IMAGE_DIM = 784  # 28 x 28 pixels, achatados


class VAE(nn.Module):
    """Autoencoder variacional com a arquitetura fixada pelo enunciado.

    * Encoder: ``784 → 512 → 256``, ReLU após cada camada;
    * Cabeças: duas camadas lineares ``256 → d``, uma para :math:`\\mu` e outra
      para :math:`\\log \\sigma^2`;
    * Decoder: ``d → 256 → 512 → 784``, ReLU nas escondidas e sigmoide na saída.
    """

    def __init__(self, latent_dim: int) -> None:
        super().__init__()
        self.latent_dim = latent_dim

        self.encoder = nn.Sequential(
            nn.Linear(IMAGE_DIM, 512),
            nn.ReLU(),
            nn.Linear(512, 256),
            nn.ReLU(),
        )
        # Cabeças separadas: a rede prevê log(sigma^2), não sigma. Prever o log
        # deixa a saída livre em toda a reta real (não há restrição de
        # positividade a impor) e a exponencial devolve uma variância positiva.
        self.fc_mu = nn.Linear(256, latent_dim)
        self.fc_logvar = nn.Linear(256, latent_dim)

        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 256),
            nn.ReLU(),
            nn.Linear(256, 512),
            nn.ReLU(),
            nn.Linear(512, IMAGE_DIM),
            nn.Sigmoid(),
        )

    def encode(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        """Devolve ``(mu, logvar)`` do posterior aproximado :math:`q(z \\mid x)`."""
        hidden = self.encoder(x)
        return self.fc_mu(hidden), self.fc_logvar(hidden)

    def reparameterize(self, mu: torch.Tensor, logvar: torch.Tensor) -> torch.Tensor:
        """Truque da reparametrização: :math:`z = \\mu + \\sigma \\odot \\varepsilon`.

        Amostrar :math:`z \\sim \\mathcal{N}(\\mu, \\sigma^2)` diretamente cortaria
        o grafo — a amostragem não é diferenciável em relação a ``mu`` e
        ``logvar``. Escrevendo :math:`z` como uma função determinística dos
        parâmetros mais um ruído :math:`\\varepsilon \\sim \\mathcal{N}(0, I)`
        **independente deles**, o gradiente volta a fluir para o encoder.

        De ``logvar`` para o desvio: :math:`\\sigma = \\exp(\\tfrac{1}{2}\\log\\sigma^2)`.
        """
        std = torch.exp(0.5 * logvar)
        eps = torch.randn_like(std)
        return mu + eps * std

    def decode(self, z: torch.Tensor) -> torch.Tensor:
        """Decodifica ``z`` para probabilidades de pixel em :math:`[0, 1]`."""
        return self.decoder(z)

    def forward(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
        mu, logvar = self.encode(x)
        z = self.reparameterize(mu, logvar)
        return self.decode(z), mu, logvar

    @torch.no_grad()
    def sample(self, n_samples: int, device: torch.device) -> torch.Tensor:
        """Amostra ``n_samples`` do prior :math:`\\mathcal{N}(0, I)` e decodifica."""
        z = torch.randn(n_samples, self.latent_dim, device=device)
        return self.decode(z)


def reconstruction_bce(x_hat: torch.Tensor, x: torch.Tensor) -> torch.Tensor:
    """BCE **somada sobre os 784 pixels**, somada sobre o lote.

    Quem divide pelo tamanho do lote é o chamador, para obter nats por imagem.
    Usar ``reduction="mean"`` aqui estaria errado: ela também faria a média sobre
    os pixels, encolhendo o termo de reconstrução 784 vezes em relação à KL — o
    mesmo que definir :math:`\\beta \\approx 784` sem perceber.
    """
    return F.binary_cross_entropy(x_hat, x, reduction="sum")


def kl_divergence(mu: torch.Tensor, logvar: torch.Tensor) -> torch.Tensor:
    """KL fechada entre :math:`q(z \\mid x)` e o prior :math:`\\mathcal{N}(0, I)`.

    .. math::
        D_{KL} = \\tfrac{1}{2}\\sum_{i=1}^{d}
                 \\left(\\mu_i^2 + \\sigma_i^2 - 1 - \\log \\sigma_i^2\\right)

    Escrita termo a termo, com :math:`\\sigma^2 = \\exp(\\log\\sigma^2)`. Somada
    sobre as dimensões latentes e sobre o lote; o chamador divide pelo tamanho do
    lote.
    """
    return 0.5 * torch.sum(mu.pow(2) + logvar.exp() - 1.0 - logvar)


def vae_loss(
    x_hat: torch.Tensor, x: torch.Tensor, mu: torch.Tensor, logvar: torch.Tensor, beta: float = 1.0
) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
    """Perda do VAE. Devolve ``(total, bce, kl)``, **em nats por imagem**."""
    batch_size = x.shape[0]
    bce = reconstruction_bce(x_hat, x) / batch_size
    kl = kl_divergence(mu, logvar) / batch_size
    return bce + beta * kl, bce, kl


@torch.no_grad()
def evaluate(model: VAE, loader: Any, device: torch.device, beta: float = 1.0) -> dict[str, float]:
    """Média de BCE e KL sobre um conjunto inteiro, em nats por imagem."""
    model.eval()
    totals = {"bce": 0.0, "kl": 0.0}
    n_images = 0
    for images, _ in loader:
        x = images.view(images.shape[0], -1).to(device)
        x_hat, mu, logvar = model(x)
        # Reacumula somas e divide no fim: assim o último lote, possivelmente
        # menor, não pesa igual aos demais.
        totals["bce"] += reconstruction_bce(x_hat, x).item()
        totals["kl"] += kl_divergence(mu, logvar).item()
        n_images += x.shape[0]
    bce, kl = totals["bce"] / n_images, totals["kl"] / n_images
    return {"bce": bce, "kl": kl, "neg_elbo": bce + beta * kl}


def train_epoch(
    model: VAE, loader: Any, optimizer: torch.optim.Optimizer, device: torch.device, beta: float = 1.0
) -> dict[str, float]:
    """Uma época de treino. Devolve as médias de BCE e KL da própria época."""
    model.train()
    totals = {"bce": 0.0, "kl": 0.0}
    n_images = 0
    for images, _ in loader:
        x = images.view(images.shape[0], -1).to(device)
        optimizer.zero_grad(set_to_none=True)
        x_hat, mu, logvar = model(x)
        loss, bce, kl = vae_loss(x_hat, x, mu, logvar, beta)
        loss.backward()
        optimizer.step()
        totals["bce"] += bce.item() * x.shape[0]
        totals["kl"] += kl.item() * x.shape[0]
        n_images += x.shape[0]
    bce, kl = totals["bce"] / n_images, totals["kl"] / n_images
    return {"bce": bce, "kl": kl, "neg_elbo": bce + beta * kl}

    """Ponto de entrada único da entrega *VAE*.

Treina os dois modelos (d = 16 e d = 2), produz as seis figuras e imprime —
além de salvar em ``results/metrics.json`` — todos os números citados no
relatório.

Uso, a partir da raiz do repositório::

    python docs/exercises/vae/code/run_all.py

Sementes, conforme o enunciado: ``torch.manual_seed(42)`` **antes de construir
cada modelo**, e o split 50 000 / 10 000 com
``torch.Generator().manual_seed(42)``. A grade de amostras do prior da Figura 3
usa ``torch.manual_seed(0)``, também como pedido.

O conjunto de teste é usado **apenas** para os números finais de cada modelo;
todo acompanhamento durante o treino é feito na validação.
"""

from __future__ import annotations

import json
import sys
import time
from pathlib import Path
from typing import Any

import matplotlib

matplotlib.use("Agg")  # sem display

import matplotlib.pyplot as plt  # noqa: E402
import numpy as np  # noqa: E402
import torch  # noqa: E402
from scipy.stats import norm  # noqa: E402
from torch.utils.data import DataLoader, random_split  # noqa: E402
from torchvision import datasets, transforms  # noqa: E402

sys.path.insert(0, str(Path(__file__).resolve().parent))

from vae import VAE, evaluate, train_epoch  # noqa: E402

BASE = Path(__file__).resolve().parents[1]
FIGURES = BASE / "figures"
RESULTS = BASE / "results"
DATA = BASE / "data"
DPI = 150

SEED = 42
SAMPLE_SEED = 0          # semente da grade de amostras do prior (Figura 3)
BATCH_SIZE = 128
EPOCHS = 20
LEARNING_RATE = 1e-3
BETA = 1.0

EXPECTED_FIGURES = [
    "figure_01_loss_curves.png",
    "figure_02_reconstructions.png",
    "figure_03_prior_samples.png",
    "figure_04_latent_scatter.png",
    "figure_05_decoded_plane.png",
    "figure_06_interpolation.png",
]


def save_figure(fig: plt.Figure, filename: str) -> str:
    FIGURES.mkdir(parents=True, exist_ok=True)
    fig.tight_layout()
    fig.savefig(FIGURES / filename, dpi=DPI)
    plt.close(fig)
    return filename


def load_data() -> dict[str, Any]:
    """Carrega o MNIST e faz o split exato pedido pelo enunciado."""
    transform = transforms.ToTensor()  # já coloca os pixels em [0, 1]
    train_full = datasets.MNIST(str(DATA), train=True, download=True, transform=transform)
    test = datasets.MNIST(str(DATA), train=False, download=True, transform=transform)

    train, val = random_split(
        train_full, [50_000, 10_000], generator=torch.Generator().manual_seed(SEED)
    )

    return {
        "train": train,
        "val": val,
        "test": test,
        "train_loader": DataLoader(train, batch_size=BATCH_SIZE, shuffle=True),
        "val_loader": DataLoader(val, batch_size=512, shuffle=False),
        "test_loader": DataLoader(test, batch_size=512, shuffle=False),
    }


def train_model(latent_dim: int, data: dict[str, Any], device: torch.device) -> dict[str, Any]:
    """Treina um VAE e registra BCE e KL, separadamente, em treino e validação."""
    # Semente fixada imediatamente antes de construir o modelo, para que as duas
    # corridas (d = 16 e d = 2) partam da mesma inicialização pseudo-aleatória.
    torch.manual_seed(SEED)
    model = VAE(latent_dim).to(device)
    optimizer = torch.optim.Adam(model.parameters(), lr=LEARNING_RATE)

    history = {"train_bce": [], "train_kl": [], "val_bce": [], "val_kl": []}
    started = time.perf_counter()
    for epoch in range(1, EPOCHS + 1):
        train_stats = train_epoch(model, data["train_loader"], optimizer, device, BETA)
        val_stats = evaluate(model, data["val_loader"], device, BETA)
        history["train_bce"].append(train_stats["bce"])
        history["train_kl"].append(train_stats["kl"])
        history["val_bce"].append(val_stats["bce"])
        history["val_kl"].append(val_stats["kl"])
        print(
            f"  d={latent_dim:>2} época {epoch:>2}/{EPOCHS} | "
            f"treino BCE {train_stats['bce']:7.3f} KL {train_stats['kl']:6.3f} | "
            f"val BCE {val_stats['bce']:7.3f} KL {val_stats['kl']:6.3f}"
        )
    elapsed = time.perf_counter() - started

    # O teste só é tocado aqui, para os números finais.
    test_stats = evaluate(model, data["test_loader"], device, BETA)
    print(
        f"  d={latent_dim} TESTE: BCE {test_stats['bce']:.3f} | KL {test_stats['kl']:.3f}"
        f" | -ELBO {test_stats['neg_elbo']:.3f} nats/imagem  ({elapsed:.1f}s)"
    )
    return {"model": model, "history": history, "test": test_stats, "seconds": elapsed}

def figure_01(history: dict[str, list[float]]) -> str:
    """Figura 1 — reconstrução e KL por época, treino e validação."""
    epochs = range(1, EPOCHS + 1)
    fig, axes = plt.subplots(1, 2, figsize=(13.0, 5.0))

    axes[0].plot(epochs, history["train_bce"], color="#1f77b4", marker="o", markersize=3, label="Treino")
    axes[0].plot(epochs, history["val_bce"], color="#d62728", marker="s", markersize=3, label="Validação")
    axes[0].set_title("Termo de reconstrução (BCE)")
    axes[0].set_ylabel("Nats por imagem (soma sobre 784 pixels)")

    axes[1].plot(epochs, history["train_kl"], color="#1f77b4", marker="o", markersize=3, label="Treino")
    axes[1].plot(epochs, history["val_kl"], color="#d62728", marker="s", markersize=3, label="Validação")
    axes[1].set_title("Termo de regularização (KL)")
    axes[1].set_ylabel("Nats por imagem (soma sobre as dimensões latentes)")

    for ax in axes:
        ax.set_xlabel("Época")
        ax.grid(alpha=0.25, linestyle=":")
        ax.legend()
    fig.suptitle("Figura 1 — Os dois termos da perda, separados ($d = 16$, $\\beta = 1$)", fontsize=13)
    fig.tight_layout(rect=(0.0, 0.0, 1.0, 0.94))
    return save_figure(fig, EXPECTED_FIGURES[0])


def figure_02(model: VAE, data: dict[str, Any], device: torch.device) -> tuple[str, list[int]]:
    """Figura 2 — primeira imagem de teste de cada dígito e sua reconstrução de mu."""
    test = data["test"]
    targets = test.targets.numpy()
    # Primeira ocorrência de cada dígito 0-9 no conjunto de teste.
    indices = [int(np.where(targets == digit)[0][0]) for digit in range(10)]
    images = torch.stack([test[i][0].view(-1) for i in indices]).to(device)

    model.eval()
    with torch.no_grad():
        mu, _ = model.encode(images)
        # Reconstrói decodificando mu — sem amostrar z (ver item E).
        reconstructions = model.decode(mu)

    fig, axes = plt.subplots(2, 10, figsize=(14.0, 3.4))

def encode_test_set(model: VAE, data: dict[str, Any], device: torch.device) -> tuple[np.ndarray, np.ndarray]:
    """Devolve ``mu`` de todas as 10 000 imagens de teste e seus rótulos."""
    model.eval()
    mus, labels = [], []
    with torch.no_grad():
        for images, targets in data["test_loader"]:
            x = images.view(images.shape[0], -1).to(device)
            mu, _ = model.encode(x)
            mus.append(mu.cpu().numpy())
            labels.append(targets.numpy())
    return np.vstack(mus), np.concatenate(labels)

def latent_overlap(mu: np.ndarray, labels: np.ndarray, n_neighbors: int = 10) -> dict[str, Any]:
    """Mede quais dígitos se sobrepõem no espaço latente, em vez de descrevê-los de olho.

    Para cada uma das 10 000 imagens de teste, olha seus ``n_neighbors`` vizinhos
    mais próximos em :math:`\\mu` e conta quantos pertencem a outro dígito. A
    contagem agregada por par é uma medida direta de quanto duas nuvens se
    interpenetram — exatamente o que o item E pergunta sobre a Figura 4.
    """
    from sklearn.neighbors import NearestNeighbors

    # n_neighbors + 1 porque o primeiro vizinho de um ponto é ele mesmo.
    finder = NearestNeighbors(n_neighbors=n_neighbors + 1).fit(mu)
    _, neighbors = finder.kneighbors(mu)
    neighbor_labels = labels[neighbors[:, 1:]]

    pair_counts: dict[tuple[int, int], int] = {}
    impurity = float(np.mean(neighbor_labels != labels[:, None]))
    for own, others in zip(labels, neighbor_labels):
        for other in others:
            if other != own:
                pair = (int(min(own, other)), int(max(own, other)))
                pair_counts[pair] = pair_counts.get(pair, 0) + 1

    total = sum(pair_counts.values())
    ranked = sorted(pair_counts.items(), key=lambda item: -item[1])
    return {
        "neighbor_impurity": impurity,
        "top_pairs": [
            {"a": a, "b": b, "count": n, "share": n / total} for (a, b), n in ranked[:6]
        ],
        "total_cross_links": total,
    }

    Exercise 1

    A — Load and split the data

    MNIST do torchvision com transforms.ToTensor(), que já coloca os pixels em \([0, 1]\), achatados em vetores de 784. As 60 000 imagens de treino são divididas exatamente como o enunciado manda:

    train, val = random_split(train_full, [50_000, 10_000],
                          generator=torch.Generator().manual_seed(42))
    Conjunto Imagens Uso
    Treino 50 000 ajuste dos pesos
    Validação 10 000 acompanhamento por época
    Teste 10 000 apenas os números finais

    B — Build the model

    Parte Camadas
    Encoder \(784 \to 512 \to 256\), ReLU após cada
    Cabeças duas lineares \(256 \to d\): uma para \(\boldsymbol{\mu}\), outra para \(\log\boldsymbol{\sigma}^2\)
    Decoder \(d \to 256 \to 512 \to 784\), ReLU nas escondidas, sigmoide na saída

    com \(d = 16\). A perda por imagem, somada sobre pixels e sobre dimensões latentes:

    \[ L = \underbrace{-\sum_{j=1}^{784}\Big[x_j \log \hat{x}_j + (1-x_j)\log(1-\hat{x}_j)\Big]}_{\text{reconstrução (BCE)}} \;+\; \beta \cdot \underbrace{\tfrac{1}{2}\sum_{i=1}^{d}\left(\mu_i^2 + \sigma_i^2 - 1 - \log\sigma_i^2\right)}_{\text{KL}} \]

    com \(\beta = 1\), média sobre as imagens do lote.

    Três decisões de implementação que valem explicação.

    A rede prevê \(\log\sigma^2\), não \(\sigma\). Prever o log deixa a saída livre em toda a reta real — não há restrição de positividade a impor — e a exponencial devolve sempre uma variância positiva. Daí \(\sigma = \exp(\tfrac{1}{2}\log\sigma^2)\).

    A reparametrização existe porque amostrar não é diferenciável. Sortear \(z \sim \mathcal{N}(\mu, \sigma^2)\) diretamente cortaria o grafo: não há gradiente de uma amostra em relação aos parâmetros que a geraram. Escrevendo

    \[ z = \mu + \sigma \odot \varepsilon, \qquad \varepsilon \sim \mathcal{N}(0, I) \]

    o ruído \(\varepsilon\) passa a ser independente de \(\mu\) e \(\sigma\), e \(z\) vira uma função determinística deles. O gradiente volta a fluir para o encoder.

    A BCE é somada, não promediada, sobre os pixels. Usa-se F.binary_cross_entropy(..., reduction="sum") dividido pelo tamanho do lote. Com reduction="mean" a média também cobriria os 784 pixels, encolhendo o termo de reconstrução 784 vezes em relação à KL — o mesmo que definir \(\beta \approx 784\) sem perceber, e o modelo ignoraria a reconstrução.

    E — Analysis

    Por que o otimizador escolhe pagar mais KL

    Na Figura 1 a KL sobe durante todo o treino enquanto a perda total cai. Parece contraditório, mas é o comportamento esperado — e a chave é enxergar a KL como preço, não como erro.

    No início, a rede está perto de \(\mu \approx 0\) e \(\log\sigma^2 \approx 0\), ou seja, \(q(z \mid x) \approx \mathcal{N}(0, I)\) para toda imagem. Esse é o estado de KL mínima — de fato a KL da primeira época de treino é 6.7438, a menor de toda a corrida. Mas é também um estado inútil: se todas as imagens mapeiam para a mesma distribuição latente, \(z\) não carrega informação alguma sobre \(x\), e o decoder só pode devolver a média do dataset. Daí a reconstrução inicial de 177.4523 nats.

    Para reconstruir, o encoder precisa fazer o oposto: dar a imagens diferentes valores de \(z\) diferentes — isto é, espalhar os \(\mu\) e encolher os \(\sigma\). E é exatamente isso que a KL cobra: os termos \(\mu_i^2\) e \(-\log\sigma_i^2\) crescem quando o posterior se afasta do prior. A KL é, com boa aproximação, a quantidade de informação sobre \(x\) que o modelo decidiu guardar em \(z\), medida em nats.

    O otimizador faz, portanto, uma troca, e os números mostram que ela compensa com folga:

    Época 1 (treino) Época 20 (treino) Variação
    Reconstrução 177.4523 80.2635 −97.1888 nats
    KL 6.7438 20.1506 +13.4068 nats
    Total 184.1961 100.4141 −83.7820 nats

    Cada nat extra de KL comprou cerca de 7.25 nats de reconstrução. A KL sobe porque vale a pena subir — e ela estabiliza em torno de 20 quando o retorno marginal se iguala ao custo.

    Por que a Figura 3 parece pior que a Figura 2 — duas razões distintas

    Razão 1 — onde as amostras do prior caem. A Figura 2 decodifica \(\mu\) de imagens reais: por construção, esses pontos estão onde o encoder efetivamente colocou dados, e o decoder treinou ali. A Figura 3 sorteia \(z \sim \mathcal{N}(0, I)\). O problema é que o posterior agregado — a média de \(q(z \mid x)\) sobre o dataset — não coincide exatamente com o prior. Ele deixa buracos: regiões com massa sob \(\mathcal{N}(0, I)\) mas sem nenhuma imagem de treino por perto. A KL de 20.5 nats é justamente a medida de quanto o posterior se afastou do prior. Uma amostra que cai num buraco é decodificada por uma parte da rede que nunca viu dado algum, e sai um borrão que não é dígito — vários visíveis na Figura 3.

    Razão 2 — o que o decoder devolve para um \(z\) dado. O decoder emite a média de uma Bernoulli por pixel, não uma imagem sorteada. Para um \(z\) qualquer existem muitas imagens plausíveis — o mesmo ponto latente é compatível com vários traçados do mesmo dígito. Minimizar a BCE leva o decoder a emitir, em cada pixel, a média sobre todas essas imagens; e a média de vários dígitos ligeiramente diferentes é uma imagem borrada. É a mesma razão pela qual as reconstruções da Figura 2 também são macias, mas o efeito é mais forte na Figura 3 porque ali o \(z\) não está preso a uma imagem específica.

    As duas razões são independentes: a primeira é sobre a geometria do espaço latente (onde se amostra) e a segunda sobre a função de perda (o que se devolve). Mesmo com um posterior agregado perfeitamente igual ao prior, a razão 2 continuaria produzindo borrões.

    Por que decodificar \(\boldsymbol{\mu}\) e não um \(z\) amostrado na Figura 2

    Porque a Figura 2 mede quanta informação sobrevive ao gargalo, e amostrar acrescentaria uma fonte de ruído que não tem nada a ver com isso. \(\boldsymbol{\mu}\) é a melhor estimativa pontual do encoder para onde aquela imagem vive no espaço latente — a média (e a moda) de \(q(z \mid x)\). Decodificá-lo responde: "da melhor representação que o modelo construiu desta imagem, quanto ele consegue recuperar?"

    Amostrar \(z = \mu + \sigma\varepsilon\) tornaria a figura não determinística: rodando duas vezes sairiam reconstruções diferentes, e parte da degradação visível seria o sorteio, não o modelo. Para uma figura cujo propósito é comparar original e reconstrução, isso é ruído que atrapalha a leitura.

    C — The decoded plane

    Por que esse espaçamento dá a cada célula a mesma massa do prior. Por definição da função de distribuição acumulada, se \(z \sim \mathcal{N}(0,1)\) então \(\Phi(z)\) é uniforme em \([0,1]\); logo, tomar \(q\) igualmente espaçado e aplicar \(z = \Phi^{-1}(q)\) faz com que passos iguais em \(q\) correspondam a incrementos iguais de probabilidade acumulada — cada uma das 15 faixas por eixo cobre \((0.95 - 0.05)/15 = 0.06\) da massa do prior.

    Espaçar linearmente em \(z\) faria o contrário: concentraria células nas caudas, onde o prior quase não tem massa e o decoder viu pouquíssimo dado de treino, e subamostraria o centro, onde está quase tudo.

Depois dele vem o agrupamento 3 / 5 / 8, cujos três pares somados (3↔8, 3↔5, 5↔8) dão 30.2 %. Juntos, esses dois focos explicam 55.9 % das ligações cruzadas. São exatamente os conjuntos que se confundem para leitores humanos: um 4 de topo fechado é um 9, e 3, 5 e 8 compartilham a mesma barriga inferior.

    A Figura 5 mostra as mesmas vizinhanças como transições contínuas, e ler as duas figuras juntas é o ponto do exercício. Percorrendo uma linha do meio da Figura 5 da esquerda para a direita, a sequência é

    \[ 2 \;\to\; 8 \;\to\; 5 \;\to\; 6 \;\to\; 4 \;\to\; 9 \;\to\; 7 \]

    e cada seta corresponde a uma fronteira entre setores vizinhos da Figura 4. As imagens intermediárias são híbridos genuínos, não misturas borradas: na passagem \(8 \to 5\) aparecem formas com o laço superior do 8 já aberto, mas a barriga inferior ainda fechada; na passagem \(4 \to 9\) — o par de maior sobreposição medida —, traços em que o topo do 4 vai se fechando até virar o laço do 9, e há colunas em que é impossível dizer qual dos dois está escrito. No canto superior a transição \(1 \to 7\) se dá por inclinação progressiva, com o traço horizontal do 7 emergindo aos poucos.

    Isso não é acidente do modelo nem defeito do treino: um 4 e um 9 são parecidos em pixels, e o encoder é premiado por reconstruir, não por separar classes — ele nunca viu os rótulos. Colocar 4 e 9 longe um do outro no plano custaria reconstrução em outras direções, sem ganho algum na perda. A sobreposição é a resposta correta ao objetivo que o modelo recebeu.

    O que duas dimensões obrigam o modelo a jogar fora

    A conta direta: \(d = 16\) guarda 16 números por imagem; \(d = 2\) guarda 2. A reconstrução piora de 80.7053 para 133.9618 nats — +53.26 nats, 66 % pior.

    A Figura 5 mostra o que foi descartado. Repare que, ao longo da grade, varia a identidade do dígito e, no máximo, uma inclinação ou largura grosseira. O que não varia é o estilo: todos os 2 da grade são essencialmente o mesmo 2 prototípico, todos os 0 o mesmo 0. Com duas coordenadas o modelo consegue construir um mapa de qual dígito é, e sobra quase nada para registrar como aquele dígito específico foi escrito — espessura do traço, inclinação individual, tamanho do laço, se o 7 tem corte, se o 1 tem a base. Essas são justamente as variações que distinguem uma amostra de outra do mesmo dígito, e é por isso que o erro de reconstrução sobe tanto.

    Em \(d = 16\) sobram dimensões para esse estilo, e por isso as reconstruções da Figura 2 preservam traços individuais — compare o 5 e o 9 originais com suas reconstruções: a inclinação particular de cada um sobrevive.

    As duas linhas da Figura 6

    A linha de cima não passa por dígitos; a de baixo passa.

    Na interpolação em pixels, os quadros intermediários (\(t\) entre 0.33 e 0.67) são uma dupla exposição: o 0 e o 8 aparecem simultaneamente, ambos a meia intensidade, sobrepostos como duas fotografias no mesmo negativo. Nenhum desses quadros é um dígito. A razão é que a média de duas imagens é uma operação sobre pixels independentes, e o conjunto das imagens que parecem dígitos não é convexo: o segmento de reta entre dois dígitos no espaço de 784 dimensões sai imediatamente desse conjunto. Não existe caneta que desenhe "metade de um 0 somado a metade de um 8"; existe apenas a sobreposição.

    Na interpolação latente, todos os dez quadros parecem dígitos. O 0 vai se estreitando e inclinando, a parte superior começa a se fechar, e por volta de \(t = 0.67\) já se lê um 8. Duas coisas explicam isso. Primeiro, o VAE aprendeu um espaço latente em que os dados ocupam uma região conexa e aproximadamente convexa — o termo de KL empurra ativamente o posterior agregado para uma gaussiana, que é convexa, de modo que o segmento entre dois pontos com dados permanece em território povoado. Segundo, o decoder só sabe produzir coisas parecidas com o que viu no treino: qualquer que seja o \(z\) de entrada, a saída é uma combinação do repertório de dígitos. Ele não tem como desenhar uma dupla exposição.

    É essa diferença que torna o espaço latente útil: operações geométricas simples nele — médias, segmentos de reta — correspondem a operações semânticas no espaço das imagens.
